== 002-replace-dependabot-with-renovate

== Status

✅ Akzeptiert (07.09.2026)

== Kontext

Wir benötigen zuverlässiges Update-Tracking für zwei Fälle: die GeoServer-Version (kein
Paket-Manager-Dependency, braucht einen Custom Regex Manager) und Docker-Base-Images mit floating
Tags wie `eclipse-temurin:21-jre-alpine`, deren Digest sich ohne Tag-Wechsel ändert.

*Entscheidungsgrundlage*:

[cols="1,2",options="header"]
|===
| Kriterium | Details

| Sicherheit | Base-Image-Digests müssen auch bei gleichbleibendem Tag aktualisiert werden.
| Modifizierbarkeit | Neue GeoServer-Releases beeinflussen keine alten Versionen.
| Testbarkeit | Update-PRs müssen die CI-Checks auslösen, damit sie nicht ungetestet mergebar sind.
|===

*Optionen*:

1. *Bei Dependabot bleiben*
* Vorteil: Kein Migrationsaufwand.
* Nachteil: Digest- und GeoServer-Version-Tracking bleiben strukturell unmöglich.
2. *Self-hosted Renovate*
* Vorteil: Auf die org-weite Einrichtung der GitHub-App kann verzichtet werden.
* Nachteil: PRs mit dem Standard-`GITHUB_TOKEN` lösen laut GitHub keine Folge-Workflows aus
  (Anti-Rekursions-Schutz). Die CI-Checks würden auf solchen PRs nie laufen, sie blieben
  ungetestet mergebar.
3. *Offizielle Renovate-GitHub-App*
* Vorteil: Docker-Digests werden bei jedem Lauf unabhängig vom Tag aktualisiert. Ein Custom Regex
  Manager trackt die GeoServer-Version gegen die GitHub-Releases, mit je einem unabhängigen Eintrag
  je Linie.
* Nachteil: Das Verhalten wird org-weit verwaltet und liegt nicht im Repo.

== Entscheidung

Wir wählen Option 3: Wir ersetzen Dependabot durch die offizielle Renovate-GitHub-App, weil:

1. Renovate aktualisiert Docker-Digests bei jedem Lauf neu, unabhängig vom Tag — dokumentiertes
   Verhalten, behebt das Ausgangsproblem direkt.
2. Ein Custom Regex Manager trackt die GeoServer-Version gegen das offzielle Geoserver Repo.
3. Löst bei PRs die CI-Checks zuverlässig aus.
4. Dependabot Security Updates (CVE-getriggerte PRs) laufen unabhängig von `dependabot.yml` weiter
   und sind von dieser Entscheidung nicht betroffen.

== Risiken

1. *Renovate-Verhalten org-weit verwaltet*: Silent Mode, Dashboard-Approval und PR-Rate-Limits
   liegen im Mend-Portal, nicht im Repo.
