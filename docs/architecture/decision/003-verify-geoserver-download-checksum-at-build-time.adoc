== 003-verify-geoserver-download-checksum-at-build-time

== Status

✅ Akzeptiert (07.09.2026)

== Kontext

Der `GEOSERVER_VERSION`-Download von SourceForge wurde bisher ohne Integritätsprüfung per `curl`
heruntergeladen. SourceForge liefert über einen RSS/Files-Feed einen MD5-Hash pro Datei, kein
SHA256.

*Entscheidungsgrundlage*:

[cols="1,2",options="header"]
|===
| Kriterium | Details

| Integrität | Der Download muss gegen Transit-Korruption und Mirror-Manipulation geprüft werden.
| Modifizierbarkeit | Renovate-Versions-Bumps dürfen keinen manuellen Zusatzschritt brauchen.
| Zuverlässigkeit | Eine fehlende oder falsche Checksum muss den Build hart abbrechen (fail-closed).
|===

*Optionen*:

1. *Keine Verifikation*
* Vorteil: Kein Aufwand.
* Nachteil: Kein Integritätsschutz.
2. *Checksum fest im Repo pinnen*
* Vorteil: Schützt zusätzlich gegen eine spätere Kompromittierung von SourceForge nach dem
  Pinning-Zeitpunkt.
* Nachteil: Jeder Renovate-Versions-Bump würde ohne manuell nachgezogene Checksum in CI
  fehlschlagen.
3. *PGP-Signatur gegen einen von GeoServer veröffentlichten Public Key*
* Vorteil: Würde auch vor einer Kompromittierung zum Pinning-Zeitpunkt selbst schützen.
* Nachteil: GeoServer bietet das nicht an. SourceForge listet keine `.asc`- oder
  `SHA256SUMS`-Dateien im Release-Verzeichnis.
4. *MD5-Hash aus SourceForges RSS-Feed zur Build-Zeit prüfen*
* Vorteil: Renovate-Versions-Bumps bleiben vollautomatisch. Schützt gegen Transit-Korruption und
  Mirror-Manipulation.
* Nachteil: Download und Checksum stammen aus derselben Quelle, und es ist nur MD5 verfügbar.

== Entscheidung

Wir wählen Option 4: Wir verifizieren den Download zur Build-Zeit gegen den MD5-Hash aus
SourceForges RSS-Feed, weil:

1. Renovate-Versions-Bumps bleiben vollautomatisch, keine manuelle Checksum-Pflege nötig.
2. Der Ansatz schützt gegen Transit-Korruption und Mirror-Manipulation, den realistischeren
   Angriffsvektor gegenüber einer kompromittierten Quelle.
3. Fehlt die Checksum oder stimmt sie nicht, bricht der Build hart ab statt still weiterzulaufen.

== Risiken

1. *Kein Schutz bei kompromittiertem SourceForge*: Download und Checksum stammen aus derselben
   Quelle.
2. *Nur MD5 verfügbar*: SourceForge liefert kein SHA256 über diesen Feed; kryptographisch
   schwächer, aber für den gewählten Schutzzweck ausreichend.
